# FPGA of the App (Vivado 2020.1)

FPGA design of an App generated with rp_dummy2, for the Red Pitaya **Ecosystem 2.0** (STEMlab 125-14,
Zynq 7010). It follows the structure of [RedPitaya-FPGA](https://github.com/RedPitaya/RedPitaya-FPGA)
Release_2026.1 (project `v0.94`, model `Z10`) as adapted for the lock-in Apps
([rp_lock-in_pid_h](https://github.com/marceluda/rp_lock-in_pid_h) v2.3.10+), with the `dummy` module of the App.
The optional Vivado 2015.2 design (0.9x scope, for Ecosystem 0.9x/1.0) is in `../fpga_eco1/` (`make eco1`
in the App folder); both use the same `prj/v0.94/rtl/dummy.v`.

## Build

Requires Vivado 2020.1 in `/tools/Xilinx/Vivado/2020.1` (or `VIVADO_SETTINGS=.../settings64.sh`).
The Makefile loads it by itself in a clean environment, so there is no need to `source` anything
(and it does not matter if Vivado 2015.2 is loaded).

```bash
make            # prj/v0.94/out/red_pitaya.bit + prj/v0.94/out/fpga.bit.bin (bootgen)
make project    # open the Vivado project (prj/v0.94/build/redpitaya.xpr) in the GUI
make clean
```

From the App folder (`..`), `make` builds the FPGA with this Makefile and copies `red_pitaya.bit`,
`fpga.bit` and `fpga.bit.bin` to the App. In Ecosystem 2.0 `fpga.sh` loads `fpga.bit.bin` with `fpgautil`
(no device tree overlay is needed: `controllerhf.so` accesses the registers through `/dev/mem`).

## Layout

```
Makefile                     make / make project / make clean
red_pitaya_vivado_Z10.tcl    Vivado script (RedPitaya-FPGA, + dummy sources, no write_hw_platform)
synCheck.sh                  post-build report (timing, critical warnings)
brd/                         board files (redpitaya 1.1)
rtl/rtl/                     common RedPitaya RTL (rp_scope_com.v has the osc_ctrl_i input, see below)
sdc/red_pitaya.xdc           pin constraints
prj/v0.94/ip/system.tcl      PS block design (Zynq PS, XADC, ...)
prj/barebones/ip/ps7_config.tcl  PS7 configuration (sourced by system.tcl)
prj/v0.94/sdc/red_pitaya.xdc timing constraints
prj/v0.94/rtl/               top (red_pitaya_top.sv), PS wrapper, scope filters
prj/v0.94/rtl/dummy.v        THE DESIGN OF THE APP (registers generated by ../config_tool.py)
prj/v0.94/rtl/dummy/         modules and ROM files (.dat) of the App: every file of the folder is synthesized
prj/v0.94/out/               build products (bit, bin, reports, logs)
prj/v0.94/build/             Vivado project (generated)
```

Module names of `prj/v0.94/rtl/dummy/` must not clash with the RedPitaya modules of `rtl/rtl/`
(the `debounce` of the template is `dummy_debounce` for that reason).

## Register map

| Address      | Block |
|--------------|-------|
| 0x40000000   | housekeeping (hk, 2.0 version) |
| 0x40100000   | oscilloscope (RedPitaya 2.0 `rp_scope_com`; inputs = dummy `osc1`/`osc2`, external trigger = dummy `trigger`) |
| 0x40200000   | (no ASG) acknowledged, reads 0 |
| 0x40300000   | PID (classic `red_pitaya_pid`) with `include_pids = True`; otherwise acknowledged, reads 0 |
| 0x40400000   | AMS / XADC |
| 0x40500000   | daisy chain |
| 0x40600000   | dummy (registers of `dummy.v`: template ones at 0x000-0x0FC, controls of app.ini from 0x100) |

Differences with the RedPitaya v0.94 design, to behave as the 2015.2 design of the template:

- DAC outputs = dummy `out1`/`out2` (+ PID outputs), saturated; dummy inputs = ADC (14 bit, 2's complement).
- The dummy `osc_ctrl` drives the scope: bit 0/1 bypass the equalization filters, bit 2 + bits 19:3 override
  the decimation (for streaming, not used by the template yet).
- Slow analog outputs: classic 250 MHz PWM driven by the dummy module (`pwm_cfg_a..d`).
- `exp_n_io[7]` = digital modulation of the dummy module (CAN0 TX if CAN is enabled).
- The external trigger pin (`exp_p_io[0]`, DIO0_P) goes into the dummy module (`external_trigger`); the scope
  external trigger is the `trigger` output of the module (Ext Trig selector `trig_sw`).
- ASG/PID regions use `sys_bus_stub_ok` (no AXI error) when they are not included.

The 2.0 scope differs from the 0.9x one in the trigger lock (0x94: every trigger locks the trigger until 1 is
written there), the status bits of `conf` (bit 2 trigger received, bit 4 acquisition done), the samples
sign-extended to 16 bits and the 20-bit decimation (up to 524288, windows of ~68 s; 0.9x: 17 bits). The C
controller (`../src/fpga.c`) handles both scopes.
